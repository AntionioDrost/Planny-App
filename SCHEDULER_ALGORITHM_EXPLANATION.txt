SHIFTPLANNER SCHEDULER ALGORITHM EXPLANATION
Plain-English explanation for non-technical readers

==================================================
0. SHORT ANSWER: THIS IS NOT AI
==================================================

The scheduler does not use AI.

It does not call ChatGPT, an OpenAI API, a machine-learning model, or any
external prediction service. It does not train itself from old schedules.
It does not "learn" employee preferences by itself. It does not make
judgements from hidden data.

The scheduler is a normal rule-based algorithm:

1. It reads the availability and settings from the app.
2. It checks which employees are allowed to work each possible shift.
3. It gives each possible assignment a score using fixed rules.
4. It builds many possible schedules.
5. It gives each complete schedule a final score.
6. It keeps the best-scoring schedule.
7. It makes a few final balancing moves if they improve the result.

Some words in the code may sound technical, such as "fairness",
"score", "candidate", "penalty", "optimization", or "iteration".
Those words do not mean AI. They simply mean that the program compares
options with a fixed formula.

The closest everyday comparison is:

"Try a lot of valid rosters, grade each roster with the same checklist,
and keep the one with the highest grade."

There is one small random element in the process. This is used only to
try slightly different choices when several options are close together.
After that, the schedule is still judged by fixed rules. This randomness
does not make the system AI. It is more like shuffling cards before
trying another normal calculation.

==================================================
1. WHAT THE SCHEDULER IS TRYING TO DO
==================================================

The scheduler tries to create a work schedule that is:

- complete enough to run the business
- valid according to availability and weekly maximums
- fair in the way hours are distributed
- practical for employees
- explainable afterwards

The main idea is:

Coverage comes first. Then fairness. Then preferences.

In more concrete terms, the scheduler tries to:

- fill normal shifts
- respect closed days
- respect employee availability
- respect weekly maximum hours
- give employees their minimum target when possible
- avoid giving too many extra hours to the same people
- place required Web and Web Revision shifts
- use Web-only employees for Web work when possible
- prefer full days for employees who have a high full-day priority
- report any shifts that could not be filled

The scheduler does not guarantee a mathematically perfect roster. It is
a practical planning algorithm. It searches through many good options,
scores them, and improves the best one with extra balancing steps.

==================================================
2. BASIC SHIFT STRUCTURE
==================================================

Every normal working day has two shift types:

- Morning: 09:00-13:00
- Afternoon: 13:00-17:00

Every shift is counted as 4 hours.

For normal staffing, each day part has room for 2 normal employees:

- 2 normal employees in the morning
- 2 normal employees in the afternoon

So a normal open day has:

- 4 normal shift places
- 16 normal working hours in total

The scheduler also supports special work:

- Web shifts
- Web Revision shifts

These special shifts are planned separately from normal staffing, but
they still count as 4 assigned hours for the employee.

==================================================
3. INPUTS USED BY THE SCHEDULER
==================================================

The scheduler receives structured data from the app. The most important
parts are:

1. Days

The list of days in the planning period.

2. Closed days

Days when the office is closed. No shifts should be planned on those
days.

3. Employees

For each employee, the scheduler knows:

- name
- availability per day
- whether the employee can do Web work
- whether the employee can do Web Revision work
- whether the employee is Web-only
- contract hours
- preferred hours
- maximum hours
- weekly preferred-hours overrides, if set
- weekly maximum-hours overrides, if set
- full-day priority

4. Weekly Web requirements

For each week, the scheduler can receive:

- how many Web shifts are wanted
- on which days Web shifts may be placed
- whether Web shifts prefer morning, afternoon, or either
- how many Web Revision shifts are wanted
- on which days Web Revision shifts may be placed
- whether Web Revision shifts prefer morning, afternoon, or either

5. Planner mode

The app supports two modes:

- fairness
- legacy

The fairness planner is the current main planner. The legacy planner is
an older rule-based planner kept as a comparison or fallback. Neither
mode uses AI.

==================================================
4. HOW AVAILABILITY IS READ
==================================================

The scheduler only assigns an employee when the availability text
matches the shift.

For a Morning shift, the employee must be available for:

- 09:00-13:00, or
- 09:00-17:00

For an Afternoon shift, the employee must be available for:

- 13:00-17:00, or
- 09:00-17:00

If the day is closed, nobody is considered available.

If the employee has no availability entry for that day, the employee is
not considered available.

Why this choice exists:

The scheduler should not guess. It only uses explicit availability from
the input. A full-day availability means the employee can work either
day part or both day parts.

==================================================
5. HOW WEEKS ARE IDENTIFIED
==================================================

The scheduler reads the week from the day label.

If a day label starts with something like:

[Week 18] Monday

then "Week 18" is used as the week ID.

If no week label is found, the scheduler uses a default week.

Why this choice exists:

Weekly preferred hours, weekly maximum hours, and weekly minimum targets
must be calculated per week. The week label lets the scheduler group the
days correctly.

==================================================
6. WEEKLY TARGETS PER EMPLOYEE
==================================================

Before assigning shifts, the scheduler calculates planning targets for
each employee in each week.

For every employee and every week, it calculates:

- available hours
- preferred hours
- minimum target
- maximum hours
- contract hours

6.1 Available hours

Available hours are calculated from availability.

Each available Morning shift counts as 4 hours.
Each available Afternoon shift counts as 4 hours.

For example:

- available Monday morning only = 4 hours
- available Monday full day = 8 hours
- available Monday full day and Tuesday afternoon = 12 hours

6.2 Preferred hours

The weekly preferred target is the smallest of:

- the employee's preferred hours for that week
- the employee's available hours for that week
- the employee's maximum hours for that week

Why this choice exists:

If someone prefers 16 hours but is only available for 8, the scheduler
should not treat 16 as realistic for that week. If someone has a maximum
of 12, the scheduler should not treat 16 as a preferred planning target.

6.3 Minimum target

The weekly minimum target is the smallest of:

- 8 hours
- the employee's preferred hours for that week
- the employee's available hours for that week
- the employee's maximum hours for that week

So the scheduler tries to move employees toward 8 hours per week when
possible, but it does not create impossible goals.

Examples:

- If someone is available for only 4 hours, the minimum target becomes 4.
- If someone has a weekly maximum of 4, the minimum target becomes 4.
- If someone has preferred hours of 4, the minimum target becomes 4.
- If someone is available enough and has enough max hours, the minimum
  target can be 8.

Why this choice exists:

The scheduler should try to give people a reasonable minimum, but it
should not punish the schedule for failing to meet a target that the
employee could not possibly work.

6.4 Cumulative targets

The scheduler also tracks cumulative preferred hours and cumulative
minimum hours across the planning period.

This means it does not only look at one week in isolation. If someone is
short in an earlier week, the scheduler can still recognize that shortfall
in a later week.

Why this choice exists:

A fair roster is not always perfectly fair inside each single week. Some
weeks have more availability problems than others. Cumulative targets let
the scheduler compensate over time when possible.

==================================================
7. HARD RULES
==================================================

The scheduler has several rules that are treated as hard restrictions
during assignment.

7.1 Closed days are not planned

If a day is marked closed, employees are not assigned there.

7.2 Availability is required

An employee can only be assigned to a day part if their availability
matches that day part.

7.3 Weekly maximum hours are respected

The normal assignment process only assigns a shift if the employee still
fits within their weekly maximum.

If nobody can take a shift without going over max, the scheduler records
the shift as unfilled instead of forcing someone over max.

7.4 Web-only employees do not receive normal shifts

Employees marked as Web-only are skipped for normal shifts.

They can receive Web or Web Revision work if they are qualified for it.

7.5 Special shifts require qualification

For a Web shift, the employee must be marked as Web-capable or Web-only.

For a Web Revision shift, the employee must be marked as Web Revision
capable.

7.6 No duplicate work on the same day part

An employee cannot be assigned twice to the same day and same shift type.

For example, one person cannot receive two Morning shifts on the same day.

7.7 Special shifts are limited per day

When assigning Web or Web Revision work, the scheduler avoids giving an
employee more than one special shift on the same day.

There is also a cleanup step at the end. If an employee somehow has more
than one special shift on the same day, the scheduler keeps the most
important special classification and turns the others back into normal
shifts.

Web Revision is treated as more important than Web in this cleanup.

Why these hard rules exist:

They protect the schedule from impossible or invalid assignments. They
also make the outcome easier to explain.

==================================================
8. SOFT PREFERENCES
==================================================

Some rules influence the score, but they do not absolutely block a shift.

8.1 Preferred hours are a soft boundary

The scheduler tries not to go above preferred hours, but preferred hours
are not as strict as maximum hours.

Why:

Preferred hours describe what is desirable. Maximum hours describe what
is allowed. Those are different concepts.

8.2 Full days are a preference

Employees can have a full-day priority.

If an employee has a higher full-day priority, the scheduler gives bonus
points when a new shift completes a full day. For example, if the employee
already has the morning and is considered for the afternoon, that can get
a bonus.

For high full-day priority employees, starting an isolated half day can
receive a small penalty.

Why:

Full days may be more practical for employees who travel farther or prefer
to work longer blocks. But the scheduler should not break coverage or
fairness just to create full days.

8.3 Web-capable normal employees are protected a little

When filling normal shifts, the scheduler applies a small penalty to using
employees who can do Web or Web Revision work.

Why:

If Web-capable people are used too quickly for normal shifts, there may
not be enough qualified people left for Web or Web Revision work later.

This is only a preference. Normal coverage can still use those employees
when needed.

8.4 Scarce shifts get priority

If only a few people can work a certain day part, that day part receives
extra attention in scoring.

Why:

Hard-to-fill shifts are risky. If the scheduler waits too long to fill
them, the few available employees may already be used elsewhere.

==================================================
9. THE FAIRNESS IDEA IN SIMPLE TERMS
==================================================

Fairness does not mean everyone gets exactly the same number of hours.

That would be unfair if people have different availability, different
maximum hours, different contract hours, or different qualifications.

Instead, the scheduler calculates what each employee can reasonably
"claim" from the schedule.

An employee's claim is based on:

- how many hours they are available
- their preferred hours
- their maximum hours
- their contract hours across the planning period
- whether they are allowed to work that type of shift

Then the scheduler compares:

- the employee's fair target
- the employee's actual assigned hours

The closer everyone is to their fair target, the lower the fairness
penalty.

9.1 Total fairness

The most important active fairness measure is total assigned hours across
the planning period.

The scheduler asks:

"Compared with their realistic claim, is this person getting too little,
too much, or about the right number of total hours?"

9.2 Normal, Web, and Revision fairness reports

The scheduler also calculates diagnostic fairness numbers for:

- normal shifts
- Web shifts
- Web Revision shifts

These are useful for reporting and understanding the schedule.

However, in the current fairness scoring, only the total-hours fairness
penalty is active in the final fairness penalty. The normal, Web, and
Revision group penalties are calculated for visibility, but their weights
are currently set to zero in the optimizer.

Why:

This keeps the main fairness target simple: distribute total hours fairly.
The system can still show diagnostic information for specific shift types.

9.3 Fairness penalty

For each employee, the scheduler calculates a load ratio:

assigned hours / target hours

If the ratio is 1.0, the employee is exactly on target.

If the ratio is below 1.0, the employee is under target.

If the ratio is above 1.0, the employee is over target.

The penalty is based on how far the ratio is from 1.0.

Why:

This rewards schedules where people are close to their fair share and
penalizes schedules where some people carry much more or much less than
their fair share.

==================================================
10. HIGH-LEVEL PROCESS
==================================================

In fairness mode, the scheduler follows this high-level process:

1. Build a single candidate schedule from the rules.
2. Score that complete schedule.
3. Repeat this many times, normally 520 times.
4. Keep the candidate schedule with the best score.
5. Rebalance the selected schedule for absolute hour distribution.
6. Return the final schedule, statistics, and reports.

Why it builds many schedules:

The order of choices can matter. If the scheduler makes one early choice,
that can affect later options. By trying many slightly different versions,
the scheduler can avoid getting stuck with a poor result caused by one
early tie or near-tie.

Why this is still not AI:

Every candidate is built using the same hand-written rules. Every final
score is calculated using the same hand-written formula. The scheduler is
not learning. It is just trying multiple rule-based outcomes.

==================================================
11. BUILDING ONE CANDIDATE SCHEDULE
==================================================

Each candidate schedule is built in phases.

The phases are:

1. Create empty schedule and counters.
2. Place required Web Revision shifts.
3. Place required Web shifts.
4. Fill normal shifts for employees below minimum targets.
5. Fill more normal shifts using fair-share logic.
6. Force-fill remaining normal capacity where possible.
7. Restore missing Web and Web Revision shifts where possible.
8. Clean up multiple special shifts on the same employee/day.
9. Rebalance shifts for total fairness.

Each phase is explained below.

==================================================
12. PHASE 1: CREATE AN EMPTY SCHEDULE
==================================================

The scheduler starts with:

- no shifts assigned
- zero assigned hours for every employee
- zero weekly assigned hours for every employee
- empty counters for unfilled normal shifts
- empty counters for unfilled Web shifts
- empty counters for unfilled Web Revision shifts
- calculated planning targets
- calculated fairness targets

Why:

This creates a clean planning context. Every assignment after this updates
the schedule, the employee hour totals, and the fairness calculations.

==================================================
13. PHASE 2: PLACE REQUIRED WEB REVISION SHIFTS
==================================================

For each week, the scheduler first tries to place the required Web
Revision shifts.

For each required Web Revision shift, it:

1. Looks at the allowed days for that week.
2. Applies the time preference:
   - Morning means try Morning first, then Afternoon.
   - Afternoon means try Afternoon first, then Morning.
   - Any means Morning and Afternoon are both acceptable.
3. Orders the allowed days by scarcity.
4. Finds employees who:
   - are qualified for Web Revision
   - are available for the day part
   - are not already working that exact day part
   - do not already have a special shift that day
   - still fit within weekly max hours
5. Scores each valid candidate.
6. Assigns the highest-scoring candidate.

Why Revision is placed before normal work:

Revision work requires a smaller qualified group. If the scheduler waits
too long, the few qualified employees may already be used elsewhere.

==================================================
14. PHASE 3: PLACE REQUIRED WEB SHIFTS
==================================================

After Web Revision shifts, the scheduler places required Web shifts.

The process is similar:

1. Look at allowed Web days for the week.
2. Follow the Web time preference.
3. Try scarce days first.
4. Consider only qualified Web employees.
5. Skip unavailable employees.
6. Skip employees already working that day part.
7. Skip employees already holding a special shift that day.
8. Skip employees who would exceed weekly max.
9. Score candidates.
10. Assign the highest-scoring candidate.

Web-only employees receive a strong preference for Web work.

Why:

If someone is Web-only, Web work is their main way to contribute to the
schedule. Also, using Web-only people for Web work preserves regular
employees for normal coverage.

==================================================
15. PHASE 4: FILL NORMAL SHIFTS TOWARD MINIMUM HOURS
==================================================

After initial special shifts, the scheduler starts filling normal shifts.

The first normal-shift phase focuses on employees who are below their
minimum target.

For each week, the scheduler repeatedly searches all open normal shift
places and all valid normal employees.

A normal candidate must:

- not be Web-only
- be available
- not already work that same day part
- still fit within weekly max
- have a current or cumulative minimum shortfall

The scheduler calculates a score for each valid candidate and assigns the
best one. It repeats this until it cannot make more progress toward
minimum targets.

Why:

Before distributing extra hours, the scheduler tries to bring people up
to a reasonable baseline. This prevents a situation where one person gets
many extra hours while another person has not reached their minimum.

==================================================
16. PHASE 5: DISTRIBUTE MORE NORMAL SHIFTS FAIRLY
==================================================

After the minimum-focused phase, the scheduler continues filling normal
shifts.

This phase can assign normal shifts to valid employees even if they are
not below minimum anymore.

The score still looks at fairness:

- people with fewer hours relative to their fair target are favored
- people already above their fair share are penalized
- people already above preferred hours are penalized
- scarce shifts are still prioritized
- full-day preferences still matter
- weekly max remains a hard limit

Why:

Once minimum targets are handled as well as possible, the remaining hours
should be spread fairly instead of simply going to the first available
employee.

==================================================
17. PHASE 6: FORCE-FILL REMAINING NORMAL CAPACITY
==================================================

Normal coverage is the highest operational priority.

After the fairness phases, the scheduler checks every normal day part.
It sorts day parts by how hard they are to fill. The day parts with the
fewest available candidates are handled first.

For each day part, while fewer than 2 normal employees are assigned:

1. Find all valid employees who can take the normal shift.
2. Exclude Web-only employees.
3. Exclude unavailable employees.
4. Exclude employees already working that exact day part.
5. Exclude employees who would exceed weekly max.
6. Score the valid candidates in force-fill mode.
7. Assign the best candidate.

Force-fill mode still uses scoring, but it is more willing to go above
preferred hours because normal coverage is very important.

However, weekly max is still checked before assigning.

Why:

Preferred hours are flexible. Open normal shifts are a much larger
problem. But maximum hours should still be respected.

==================================================
18. PHASE 7: CONVERT SPECIAL SHIFTS TO NORMAL IF NEEDED
==================================================

Sometimes a normal day part still has too few normal employees, but an
employee is already working a Web or Web Revision shift on that exact day
part.

In that case, the scheduler may convert that employee's special shift
into a normal shift.

This is only used to repair normal coverage.

Why:

Normal shifts are the core staffing requirement. If a normal slot cannot
be filled another way, a special shift may need to be sacrificed.

The scheduler later tries to restore missing special shifts if possible.

==================================================
19. PHASE 8: RECORD UNFILLED NORMAL SHIFTS
==================================================

If a normal shift is still not filled after:

- normal candidate assignment
- force-fill attempts
- converting special work to normal work

then the scheduler records the missing normal shift as unfilled.

Why:

The scheduler should be honest. If the input data makes full coverage
impossible, the output must show that instead of hiding the problem.

==================================================
20. PHASE 9: RESTORE OR ADD WEB AND WEB REVISION SHIFTS
==================================================

After normal coverage is handled, the scheduler checks whether the weekly
Web and Web Revision targets have been met.

For each missing special shift, it tries two strategies.

Strategy 1: assign an idle qualified employee

The scheduler searches for someone who:

- is qualified for that special type
- is available
- is not already working that day part
- does not already have a special shift that day
- still fits within weekly max

If found, it assigns the special shift.

Strategy 2: convert a normal shift and replace it

If no idle qualified employee is available, the scheduler looks for a
qualified employee who is already working a normal shift on that allowed
day part.

It can then:

1. Change that employee's normal shift into a Web or Web Revision shift.
2. Find another normal employee to replace the normal coverage.

The scheduler scores the combined move before choosing it.

Why:

This protects normal coverage while still trying to meet special-shift
requirements. The scheduler does not simply convert normal work to Web
work and leave a normal hole behind.

==================================================
21. PHASE 10: RECORD UNFILLED SPECIAL SHIFTS
==================================================

If a Web or Web Revision target still cannot be met, the scheduler records
the missing special shift as unfilled.

Why:

Again, the scheduler should not pretend that an impossible requirement was
met. If there are not enough qualified and available people, the output
must show that.

==================================================
22. PHASE 11: CLEAN UP MULTIPLE SPECIAL SHIFTS ON ONE DAY
==================================================

At the end of candidate construction, the scheduler checks every employee
day by day.

If an employee has more than one special shift on the same day, the
scheduler keeps only one special classification.

Priority is:

1. Web Revision
2. Web

Any extra special shift on that same day is converted back to normal.

Why:

This keeps special work from stacking oddly on one person in a single
day. Revision is kept first because it is more specialized.

==================================================
23. PHASE 12: REBALANCE FOR TOTAL FAIRNESS
==================================================

After one candidate schedule has been built, the scheduler tries to
improve total-hours fairness.

It can perform up to 40 improvement moves.

For each possible move, it asks:

- Can this shift be moved from one employee to another?
- Would the receiving employee be available?
- Would the receiving employee be qualified?
- Would the receiving employee stay within weekly max?
- Would the special-shift rules still be valid?
- Would total fairness improve?

For normal shifts:

- the shift stays on the same day and same day part

For Web or Web Revision shifts:

- the shift may move within the allowed special days and allowed time
  types for that same week

If a move improves the total fairness penalty, the scheduler applies the
best move and checks again.

It stops when no improving move exists or after 40 iterations.

Why:

The first construction pass makes many good choices, but it cannot always
see every later consequence. This rebalance step improves the result after
the full schedule is visible.

==================================================
24. HOW INDIVIDUAL CANDIDATES ARE SCORED
==================================================

When the scheduler considers assigning a shift to an employee, it gives
that possible assignment a score.

The highest-scoring valid candidate wins.

The score is not a mystery. It is a fixed formula with bonuses and
penalties.

24.1 Normal shift scoring

For normal shifts, the score looks at:

- current weekly minimum shortfall
- cumulative minimum shortfall
- how many hours the employee already has above minimum
- how many cumulative extra hours the employee already has
- whether the shift is hard to fill
- whether the shift completes a full day
- whether the employee is Web-capable and might be needed for Web work
- whether the employee has few remaining opportunities this week
- whether this is a last chance to meet the employee's minimum target
- whether the employee was already over preferred in the previous week
- whether the assignment would go above preferred hours
- whether the assignment would go above maximum hours
- projected total-hours fairness impact
- a very small random tie-breaking value

Important:

The score can penalize going above maximum, but normal assignment also
filters out candidates who would exceed max. So max is protected before
the score is even used.

24.2 Web and Web Revision scoring

For special shifts, the score looks at many of the same things, plus:

- whether the employee is Web-only
- whether the employee is specifically qualified for Revision
- whether using a normal employee for Web would hurt normal coverage
- how scarce the special shift is

Web-only employees receive a strong bonus for special work.

Why:

They cannot help with normal shifts, so assigning them to special work is
usually efficient and fair.

24.3 Fairness impact inside candidate scoring

Before assigning a candidate, the scheduler estimates how the assignment
would affect the total fairness penalty.

If the assignment would make fairness worse, the score is reduced.

If it helps a lagging employee move closer to target, it becomes more
attractive.

Why:

Fairness should influence choices while the schedule is being built, not
only after the schedule is finished.

24.4 Small random noise

The score includes a small random value.

This is intentionally small. It does not replace the rules. It only helps
the scheduler try different options when candidates are close.

Why:

Without this, the scheduler may make the same early tie-break every time.
Trying many slight variations gives the final scoring step more options.

24.5 Important distinction: candidate score vs final schedule score

There are two different scoring levels:

1. Candidate score

This is used while building a schedule. It answers:

"For this one open shift, which employee is the best choice right now?"

2. Final schedule score

This is used after a complete schedule has been built. It answers:

"Compared with all other complete schedules we tried, is this whole
schedule better or worse?"

The candidate score helps the scheduler make local decisions. The final
schedule score decides which complete roster wins.

This distinction matters because a choice can look good locally but still
lead to a weaker overall roster. That is why the scheduler builds many
candidate rosters and then compares the complete outcomes.

24.6 Exact candidate scoring values

The candidate scoring values are hand-written weights. They are not
learned by AI and they are not calculated from old schedules.

They are chosen to express business priorities:

- minimum-hour problems should matter a lot
- scarce shifts should be handled early
- weekly max should be protected
- preferred hours should matter, but less than hard coverage
- Web-qualified people should not be used carelessly for normal work
- full days should help when practical, but not dominate the roster
- fairness should influence every assignment

The exact base weights used by the fairness planner are:

- weekMinimum: 94
- cumulativeMinimum: 66
- weekFairness: 8
- cumulativeFairness: 5
- scarcity: 30
- fullDay: 1
- protectWeb: 24
- protectRevision: 36
- overPreferred: 8
- overMax: 22
- noise: 6

These numbers are relative. A value of 94 does not mean "94 euros" or
"94 percent". It means "this factor is much more important than a factor
with weight 8, and less important than a factor with a later penalty of
50,000".

24.7 Normal shift candidate scoring

For a normal shift, the scheduler starts at zero and adds or subtracts
points.

The main normal-shift scoring values are:

- Weekly minimum need:
  +159.8 at full weekly minimum need
  This comes from 94 * 1.7.

- Cumulative minimum need:
  +82.5 at full cumulative minimum need
  This comes from 66 * 1.25.

- Concrete weekly minimum debt:
  +26 per missing 4-hour shift, capped at 2 shifts
  The maximum bonus from this part is +52.

- Extra hours above weekly minimum:
  -8 per hour

- Extra hours above cumulative minimum:
  -5 per hour

- Scarcity:
  +30 per scarcity point
  Scarcity is higher when fewer people can work that day part.

- Full-day pattern:
  Uses the full-day bonus or penalty described below.

- Protect Web-capable employees:
  -24 when using a Web-capable normal employee for normal work
  -36 when using a Web Revision-capable normal employee for normal work

- Few remaining normal opportunities:
  +28 when the employee has 2 or fewer remaining normal opportunities
  +12 when the employee has 3 or 4 remaining normal opportunities

- Last chance pressure:
  +54 per pressure point when the employee is running out of chances to
  reach minimum

- Previous week over preferred:
  -8 times the previous-week over-preferred ratio

- Weekly over preferred, normal mode:
  -14.4 per hour
  This comes from 8 * 1.8.

- Cumulative over preferred, normal mode:
  -6.4 per hour
  This comes from 8 * 0.8.

- Weekly over preferred, force-fill mode:
  -9.6 per hour
  This comes from 8 * 1.2.

- Cumulative over preferred, force-fill mode:
  -4.8 per hour
  This comes from 8 * 0.6.

- Weekly over max, force-fill mode:
  -31.9 per hour
  This comes from 22 * 1.45.

- Safety penalty if projected weekly max is exceeded:
  -360 in normal mode
  -180 in force-fill mode

- Fairness impact:
  -90 times the projected fairness penalty increase

- Random exploration:
  +0 to +6

The weekly max penalties are mostly a safety layer, because normal
candidate selection already filters out employees who would exceed their
weekly max.

During the minimum-hours phase, the scheduler adds an extra +90 to the
normal candidate score. This deliberately gives priority to employees who
are below their minimum target.

During the fair-share phase, the scheduler adds an extra +24. This keeps
normal filling moving after minimum targets have been handled, but it is
less forceful than the minimum-hours phase.

Why these values are shaped this way:

- The largest positive local signals are minimum need and scarcity,
  because the scheduler should first help people who are short and protect
  hard-to-fill shifts.
- Extra hours above minimum are penalized gradually, so one employee does
  not keep receiving extra hours while others are behind.
- Preferred-hour penalties are meaningful but not absolute.
- Full-day preference is a bonus, not the main driver.
- Random noise is intentionally tiny compared with the important factors.

24.8 Web and Web Revision candidate scoring

Special-shift scoring is similar, but it has extra rules for qualification
and normal-coverage protection.

The main Web and Web Revision candidate scoring values are:

- Weekly minimum need:
  +122.2 at full weekly minimum need
  This comes from 94 * 1.3.

- Cumulative minimum need:
  +66 at full cumulative minimum need

- Extra hours above weekly minimum:
  -8 per hour

- Extra hours above cumulative minimum:
  -5 per hour

- Special-shift scarcity:
  +36 per scarcity point
  This comes from scarcity weight 30 plus 6 extra points.

- Full-day pattern:
  Uses the full-day bonus or penalty described below.

- Web-only employee:
  +220 inside the base special score
  and an additional +1200 when directly choosing a qualified special
  candidate for an open special shift.

- Revision qualification:
  +32 for a Web Revision shift when the employee is revision-capable

- Normal Web qualification:
  +12 for a Web shift when the employee is Web-capable and not Web-only

- Protect normal coverage:
  If the employee is not Web-only and normal staffing is scarce, subtract
  16 points per normal-scarcity point.

- Previous week over preferred:
  -7 times the previous-week over-preferred ratio

- Weekly over preferred:
  -15.2 per hour
  This comes from 8 * 1.9.

- Cumulative over preferred:
  -7.2 per hour
  This comes from 8 * 0.9.

- Weekly over max:
  -33 per hour
  This comes from 22 * 1.5.

- Safety penalty if projected weekly max is exceeded:
  -280

- Fairness impact:
  -90 times the projected fairness penalty increase

- Random exploration:
  +0 to +6

Why Web-only has such a large bonus:

A Web-only employee cannot fill normal work. If they are available and
qualified for Web work, using them for Web work is usually very efficient:
it fills the special requirement without taking a normal worker away from
normal coverage.

Why normal scarcity can penalize special assignments:

If a normal employee is also qualified for Web, assigning that person to
Web may create a normal staffing problem. The scheduler therefore checks
whether normal coverage is scarce before using normal employees for
special work.

24.9 Full-day scoring values

Full-day preference appears in both candidate scoring and final schedule
scoring.

During candidate scoring:

- If the employee already has the other half of the day and has full-day
  priority 2 or higher:
  +36 + priority * 14

- If the employee has no shift yet that day, has full-day priority 4 or
  higher, and the shift is not Revision:
  -12 - priority * 4

During final schedule scoring:

- If the employee has 2 or more shifts on a day and full-day priority is
  2 or higher:
  +90 + priority * 14

- If the employee has a shift that does not become a full day and full-day
  priority is 4 or higher:
  -22 - priority * 6

Why:

This makes full days attractive for people who strongly prefer them, but
the values are still much smaller than the penalties for missing normal
coverage or failing minimum hours.

24.10 Why the values are not "perfect"

The scoring values are practical tuning values.

They are chosen to reflect the intended priority order:

1. Do not leave normal staffing open if it can be avoided.
2. Respect hard limits such as availability and max hours.
3. Help employees reach realistic minimums.
4. Keep the total distribution fair.
5. Preserve special-shift capacity.
6. Avoid unnecessary preferred-hour overages.
7. Prefer practical full days.

These values can be adjusted if management wants different behavior. For
example:

- A higher preferred-hour penalty would make the scheduler avoid extra
  hours more strongly.
- A higher full-day bonus would create more full days.
- A higher Web unfilled penalty would make Web coverage more important.
- A higher fairness weight would make hour balance more important.

Changing the values does not add AI. It changes the rulebook.

==================================================
25. HOW A COMPLETE SCHEDULE IS SCORED
==================================================

After a complete candidate schedule is built, the scheduler gives the
whole schedule a final score.

The final score is used to compare one full candidate schedule against
another full candidate schedule.

The scheduler heavily penalizes:

- unfilled normal shifts
- employees below weekly minimum
- employees below cumulative minimum
- employees above weekly maximum
- employees above preferred hours
- employees above cumulative preferred hours
- poor total-hours fairness
- uneven absolute hour distribution

It also gives smaller bonuses or penalties for:

- good full-day patterns
- Web-only employees being used for special work

25.1 Normal unfilled shifts receive the biggest penalty

Each missing normal Morning or Afternoon place receives a very large
penalty.

Why:

Normal coverage is the main operational requirement. A schedule with open
normal work should almost always lose against a schedule with better
normal coverage.

25.2 Web and Revision unfilled shifts also receive penalties

Missing Web and Web Revision shifts are penalized too, but less heavily
than missing normal coverage.

Revision has a larger unfilled penalty than normal Web.

Why:

Special work matters, but normal staffing is the foundation. Revision is
more specialized than normal Web, so it gets a stronger penalty.

25.3 Minimum shortfalls are heavily penalized

If an employee is below weekly minimum, the schedule loses points.

If an employee is below cumulative minimum, the schedule also loses
points.

Why:

The scheduler should actively try to give employees their minimum hours
where possible, both in the current week and across the planning period.

25.4 Maximum-hour violations are heavily penalized

If a schedule somehow has an employee above weekly maximum, it loses many
points.

Why:

Maximum hours are a hard planning boundary.

25.5 Preferred-hour overages are penalized more softly

Going above preferred hours loses points, but not as severely as missing
normal coverage or breaking maximum hours.

Why:

Preferred hours are important, but they are a preference. They are not the
same as maximum hours.

25.6 Fairness penalty is part of the final score

The scheduler subtracts a fairness penalty based on total-hours fairness.

Why:

The best schedule should not only be complete. It should also distribute
hours in a fair way according to realistic employee claims.

25.7 Absolute hour distribution is also considered

The scheduler calculates a Gini coefficient over total assigned hours.

In simple terms, the Gini coefficient measures how uneven the total hours
are across employees.

Lower is more even.

Why:

The fairness target already accounts for realistic claims. The absolute
hours check is an extra balancing signal so the final roster does not end
up unnecessarily uneven in raw assigned hours.

25.8 Exact final schedule scoring values

The final schedule score uses larger values than the local candidate
score because it judges the whole roster.

The exact final penalties and bonuses are:

- Missing normal shift:
  -50,000 per missing normal shift place

- Missing Web shift:
  -1,200 per missing Web shift

- Missing Web Revision shift:
  -1,600 per missing Web Revision shift

- Below weekly minimum:
  -2,600 per missing hour

- Below cumulative minimum:
  -1,800 per missing hour

- Above weekly maximum:
  -2,600 per extra hour

- Above weekly preferred:
  -140 per extra hour

- Above cumulative preferred:
  -60 per extra hour

- Total fairness penalty:
  -180 times the total fairness penalty

- Absolute-hours Gini:
  -1,440 times the absolute-hours Gini coefficient
  This comes from 180 * 8.

- Full day:
  +90 + priority * 14 when an employee with priority 2 or higher has 2 or
  more shifts on a day

- Incomplete day for high full-day priority:
  -22 - priority * 6 when an employee with priority 4 or higher has a
  working day that does not become a full day

- Web-only employee doing only special work that day:
  +16

25.9 Why the final score values are chosen this way

The exact numbers are mainly about relative importance.

The most important example is the missing normal shift penalty:

- one missing normal shift place = -50,000

That is intentionally huge. It means a roster with missing normal staffing
will usually lose against a roster that fills normal staffing, even if the
second roster is a little less pretty in other ways.

Minimum and maximum problems are also very expensive:

- 4 hours below weekly minimum = -10,400
- 4 hours above weekly max = -10,400

This makes minimum and max much more important than preferred-hour
overages:

- 4 hours above preferred = -560

That expresses the business rule:

"Preferred hours matter, but they are not as important as coverage,
minimum-hour fairness, or maximum-hour boundaries."

Special shifts are important, but they are below normal coverage:

- missing Web = -1,200
- missing Web Revision = -1,600
- missing normal = -50,000

This means the scheduler should try hard to place Web and Revision work,
but not at the cost of breaking normal staffing.

The fairness and Gini weights are moderate:

- total fairness penalty is multiplied by 180
- absolute-hours Gini is multiplied by 1,440

These numbers make fairness matter across close schedules, but they do
not normally overpower a large operational problem such as missing normal
coverage.

The full-day bonus is positive but smaller:

- for common priorities 2 to 5, a full day is worth around +118 to +160

This makes full days attractive when the schedule has room for them, but
not more important than coverage or fairness.

In short:

- 50,000-level values protect core staffing.
- 2,600-level values protect minimum and max-hour rules.
- 1,200 to 1,600 values protect special-shift requirements.
- 140 and 60 values keep preferred hours in mind.
- 180 and 1,440 values guide fairness and balance.
- 100-level values guide full-day convenience.

==================================================
26. CHOOSING THE BEST OF MANY CANDIDATES
==================================================

By default, the scheduler builds 520 candidate schedules.

For each candidate:

1. Build the candidate using the phase process.
2. Score the candidate with the final scoring formula.
3. Compare it with the best candidate so far.
4. Keep it only if it scores better.

After all iterations, the highest-scoring schedule is selected.

Why:

Scheduling has many competing goals. A single pass can make a reasonable
schedule, but trying many passes gives the scheduler more chances to find
a better combination.

This is a standard heuristic search approach. It is not AI.

==================================================
27. FINAL REBALANCE FOR ABSOLUTE HOURS
==================================================

After the best candidate schedule is selected, the scheduler performs one
more balancing step.

This step tries to reduce uneven total assigned hours.

It can perform up to 40 moves.

For each possible move, it checks:

- the move must reduce absolute hour inequality
- the receiving employee must be valid for the shift
- the receiving employee must stay within weekly max
- special shifts must remain on allowed days and times
- the move must not make the fairness penalty too much worse
- the combined objective must improve

The combined objective is:

total fairness penalty + absolute-hours inequality penalty

The exact rebalance values are:

- maximum number of total-fairness rebalance moves:
  40

- maximum number of absolute-hours rebalance moves:
  40

- absolute-hours inequality weight during final rebalance:
  8

- final rebalance objective:
  total fairness penalty + absolute-hours Gini * 8

- allowed fairness penalty headroom:
  initial fairness penalty + the larger of:
  0.2, or 75 percent of the initial fairness penalty

Why:

The selected schedule may be best by the main score, but there may still
be small safe swaps that make total hours more evenly distributed. This
step applies those swaps only when they improve the balance enough and do
not damage the fairness result too much.

==================================================
28. WHAT THE FINAL OUTPUT CONTAINS
==================================================

The scheduler returns a structured result with:

1. Planner mode

This says whether the result came from fairness mode or legacy mode.

2. Employee schedules

For each employee, the assigned shifts are listed.

Each assigned shift contains:

- day
- Morning or Afternoon
- whether it is Web
- whether it is Web Revision

3. Unfilled normal shifts

For each day, the result says how many normal Morning and Afternoon
places could not be filled.

4. Unfilled Web shifts

For each day, the result says how many Web shifts could not be filled.

5. Unfilled Web Revision shifts

For each day, the result says how many Web Revision shifts could not be
filled.

6. Fairness report

This includes:

- total demand hours
- active employees per fairness group
- each employee's claim hours
- each employee's target hours
- each employee's assigned hours
- each employee's load ratio
- fairness penalties
- Jain index
- Gini coefficient
- coefficient of variation

These metrics help explain how balanced the result is.

6.1 Fairness metrics explained

The fairness report contains several terms that sound mathematical. In
plain English, they are different ways to describe whether the roster is
balanced.

Claim hours

Claim hours mean:

"How many hours can this employee reasonably claim from this type of work?"

For total hours, claim hours are based on:

- availability
- preferred hours
- maximum hours
- contract hours across the planning period

For normal shifts, Web-only employees have a normal claim of zero because
they are not supposed to work normal shifts.

For Web shifts, only Web-qualified employees can have a Web claim.

For Web Revision shifts, only Revision-qualified employees can have a
Revision claim.

Why:

Fairness should not compare people who are not equally able or allowed to
work the same type of shift.

Demand hours

Demand hours mean:

"How many hours of this work type need to be assigned?"

For normal work, demand is calculated from:

active days * 2 day parts * 2 normal employees * 4 hours

For Web and Web Revision, demand is calculated from the configured weekly
requirements:

number of required shifts * 4 hours

Sum claims

Sum claims means all eligible employees' claim hours added together.

Target hours

Target hours are the employee's fair share of the demand.

The formula is:

target hours = demand hours * employee claim hours / sum of all claims

Example:

If the schedule has 40 hours of demand and one employee has 25 percent of
the total claim, that employee's target is 10 hours.

Assigned hours

Assigned hours are the hours the employee actually received.

Load ratio

Load ratio compares actual assigned hours with target hours:

load ratio = assigned hours / target hours

Examples:

- 1.00 means exactly on target
- 0.75 means the employee received 75 percent of their fair target
- 1.25 means the employee received 125 percent of their fair target

Penalty

The fairness penalty measures how far the load ratio is from 1.00.

The formula is:

penalty = (load ratio - 1) squared

Examples:

- load ratio 1.00 gives penalty 0
- load ratio 0.75 gives penalty 0.0625
- load ratio 1.25 gives penalty 0.0625
- load ratio 1.50 gives penalty 0.25

Why squared:

Squaring makes larger unfairness grow faster. Being a little off target is
not terrible. Being far off target becomes much more expensive.

Total penalty

The report calculates penalties for total, normal, Web, and Revision
groups.

In the current optimizer, the group weights are:

- total: 1.0
- normal: 0
- Web: 0
- Revision: 0

So the active fairness penalty is the total-hours penalty. The normal,
Web, and Revision fairness numbers are still useful diagnostics, but they
do not currently add to the optimizer's total fairness penalty.

6.2 Jain index explained

The Jain index is a fairness score.

It is calculated from the employees' load ratios.

Simple meaning:

- closer to 1.00 is better
- 1.00 means everyone has the same load ratio
- lower values mean the load ratios are more uneven

Why it is useful:

It gives a single "higher is better" number for fairness. If two rosters
have the same coverage, the one with the higher Jain index is usually more
balanced.

Important:

The scheduler uses load ratios, not raw hours, for this report. That means
it compares people against their fair targets, not against identical hours
for everyone.

6.3 Gini coefficient explained

The Gini coefficient measures inequality.

Simple meaning:

- 0 means perfectly equal
- higher means more unequal
- lower is better

In the fairness report, Gini is calculated from load ratios. That means it
shows how uneven employees are compared with their own fair targets.

The scheduler also calculates a separate absolute-hours Gini from raw
total assigned hours. That one asks a simpler question:

"How uneven are the total assigned hours across employees, regardless of
their target?"

Why both are useful:

- Load-ratio Gini checks fairness relative to realistic targets.
- Absolute-hours Gini checks whether the raw hour totals are unnecessarily
  uneven.

Example:

If one employee can realistically work 8 hours and another can
realistically work 16 hours, giving both exactly 8 hours may look equal in
raw hours, but it may not be fair relative to their targets.

On the other hand, if two similar employees both have similar targets, but
one receives 4 hours and the other receives 20, absolute-hours Gini helps
show that the raw distribution is uneven.

6.4 Coefficient of variation, or CV, explained

CV means coefficient of variation.

It is:

standard deviation / average

Simple meaning:

- lower CV means the values are closer together
- higher CV means more spread
- 0 means no spread at all

Why it is useful:

CV is another way to describe spread. It is scale-independent, so it can
compare variation even when the average changes.

In this scheduler, CV is also calculated from load ratios in each fairness
group.

6.5 How to read the fairness report quickly

For a manager, the most useful quick reading is:

- Load ratio near 1.00 means the employee is close to target.
- Penalty near 0 means the employee is close to target.
- Jain index closer to 1.00 means better fairness.
- Gini closer to 0 means less inequality.
- CV closer to 0 means less spread.
- Assigned hours show what actually happened.
- Target hours show what the scheduler considered fair.
- Claim hours show why that target was reasonable.

No single metric tells the whole story. The report includes several
metrics so that fairness can be checked from multiple angles.

7. Employee statistics

For each employee, the result includes:

- total assigned hours
- total preferred hours
- total maximum hours
- preferred hours per week
- assigned hours per week

==================================================
29. WHY SOME CHOICES ARE MADE
==================================================

29.1 Why special shifts are placed early

Web and Web Revision shifts require qualified people and allowed days.
Because there are fewer valid options, the scheduler tries to reserve
them early.

29.2 Why normal shifts still have the highest final priority

Normal shifts are the main staffing need. If normal coverage is missing,
the schedule may not be usable. That is why missing normal shifts receive
the largest penalty.

29.3 Why minimum hours are handled before extra fairness

It would be unfair to distribute extra hours while some employees are
still below their realistic minimum. The scheduler first tries to reduce
minimum shortfalls, then spreads remaining hours more fairly.

29.4 Why preferred hours are not hard limits

Preferred hours describe what is desired. They should guide the schedule,
but they should not automatically leave normal shifts open if someone can
still legally and practically work more.

29.5 Why maximum hours are hard limits

Maximum hours define the boundary the scheduler should not cross. The
scheduler checks max before assigning shifts.

29.6 Why scarce shifts are handled carefully

Some day parts may have only one or two possible employees. If those
employees are used elsewhere too early, the shift may become impossible
to fill. Scarcity scoring reduces that risk.

29.7 Why Web-only employees get special preference

Web-only employees cannot help with normal staffing. Giving them Web work
uses their availability without taking normal workers away from normal
coverage.

29.8 Why full days are only a soft preference

Full days can be useful and employee-friendly, but they should not
override availability, coverage, weekly max, or fairness.

29.9 Why the scheduler tries multiple schedules

There may be several reasonable candidates at any point. Trying multiple
slight variations gives the scheduler a better chance to find a strong
overall schedule.

29.10 Why final rebalancing exists

Even after the best candidate is chosen, a few shift moves may improve
fairness. The final rebalance step looks for those safe improvements.

==================================================
30. WHAT THE SCHEDULER DOES NOT DO
==================================================

The scheduler does not:

- use AI
- call an external model
- train on historical rosters
- infer hidden employee preferences
- ignore availability
- intentionally favor a person without a rule-based reason
- guarantee a perfect mathematical optimum
- hide unfilled shifts
- silently change the input data

It only works with the data and settings it receives.

==================================================
31. WHY RESULTS CAN SOMETIMES DIFFER BETWEEN RUNS
==================================================

The scheduler uses a small random value inside candidate scoring.

This means two runs with the same input can sometimes produce slightly
different schedules.

That does not mean the scheduler is learning or using AI.

It means the scheduler is exploring different valid choices. The final
selection still uses the same fixed scoring formula.

Why this is useful:

If two candidates are almost equally good, always choosing the first one
can accidentally block a better later schedule. Small randomness lets the
system try another path.

==================================================
32. LIMITATIONS
==================================================

The scheduler is practical, but it has limitations.

32.1 It depends on input quality

If availability, max hours, qualifications, or Web requirements are wrong,
the schedule can also be wrong.

32.2 It may leave shifts unfilled

If the input makes a shift impossible, the scheduler records it as
unfilled. It does not invent availability.

32.3 It is not a mathematical proof of the best possible schedule

The scheduler tries many candidates and improves them. That is usually
effective, but it is not the same as proving that no better schedule
exists anywhere.

32.4 Fairness is based on hours and configured constraints

The scheduler does not understand personal context unless that context is
entered into the data, such as availability, max hours, preferred hours,
or full-day priority.

32.5 Randomness can affect exact assignments

Because it explores many options with small random tie-breaks, exact
assignments can vary. The priorities and rules remain the same.

33. LEGACY MODE
==================================================

The app also contains a legacy planner.

If the planner mode is set to "legacy", the scheduler calls the older
legacy scheduling function instead of the fairness planner.

The legacy planner is also rule-based. It does not use AI.

The fairness planner is the newer mode and includes the current fairness
reporting and rebalancing logic described in this document.

==================================================
34. ONE-PAGE MANAGEMENT SUMMARY
==================================================

The scheduler is a rule-based planning algorithm, not AI.

It starts by reading availability, employee settings, weekly targets, and
special Web requirements. It calculates realistic weekly targets for each
employee based on availability, preferred hours, maximum hours, and
contract hours.

It then builds many possible rosters. Each roster is built in phases:
special shifts first, then normal shifts for people below minimum, then
extra normal shifts distributed fairly, then remaining normal coverage,
then special-shift restoration, then cleanup and fairness rebalancing.

Every possible assignment is scored with fixed rules. The score rewards
useful choices such as filling scarce shifts, helping employees who are
below minimum, completing full days when appropriate, and improving fair
hour distribution. The score penalizes choices such as going above
preferred hours, creating unfair hour distribution, or using scarce
qualified employees in a way that hurts coverage.

Every complete roster is then scored. Missing normal shifts receive the
largest penalty. Minimum-hour shortfalls and maximum-hour problems are
also heavily penalized. Special-shift gaps, preferred-hour overages, and
fairness imbalance also affect the score.

After trying many rosters, the scheduler keeps the best one and performs
a final rebalance to improve total hour distribution when safe.

The result is explainable because every decision comes from visible input
data and fixed scoring rules. There is no hidden model, no training, no
prediction engine, and no AI service behind it.

==================================================
35. SIMPLEST POSSIBLE EXPLANATION
==================================================

The scheduler works like a very strict checklist:

1. Who is available?
2. Who is allowed to do this type of work?
3. Who still has room within weekly max?
4. Who needs hours most?
5. Which shift is hardest to fill?
6. Would this choice make the schedule fairer or less fair?
7. Would this help create a practical full day?
8. Would it damage normal coverage or special coverage?
9. What does the complete roster score?
10. Is this roster better than the other rosters we tried?

That checklist is applied repeatedly and consistently.

That is the algorithm.
